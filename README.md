# Kanban Margin MVP

Локальное MVP для распределения заявок по менеджерам с расчётом ожидаемой валовой маржи. Архив рассчитан на запуск из VS Code на Windows/macOS с Node.js 22+.

```bash
npm install
npm test
npm run dev
```

Frontend запускается на `http://localhost:5173`, backend — на `http://localhost:3001`.

## Netlify

Проект поддерживает деплой целиком на Netlify: frontend собирается в `frontend/dist`, а Express backend запускается как Netlify Function `api`. В Netlify укажите корень репозитория как Base directory и оставьте build settings из `netlify.toml`. После публикации локальный backend запускать не нужно: frontend обращается к `/api` на том же домене.

Для локальной разработки Vite проксирует `/api` на `http://localhost:3001`, поэтому команда `npm run dev` продолжает работать без дополнительных переменных.

Демо-вход: `employee@demo.local` / `demo-kanban`.

Backend по умолчанию использует demo-данные (70 заявок, 5 менеджеров, смешанные продукты и регионы). При первом открытии доски рассчитывается план на выбранный день. Колонки показывают новые заявки, рекомендации алгоритма, подтверждённые назначения и заявки в работе. Нажатие на менеджера открывает все его заявки за выбранный день. Клик по карточке открывает формулу, историю по региону и продукту, сглаживание малой выборки и сравнение менеджеров. В этой панели можно назначить другого менеджера или подтвердить рекомендацию. Снимок первоначальной рекомендации сохраняется. Крестик снимает назначение. Подтверждённые вручную назначения сохраняются при повторном расчёте. Снятые крестиком заявки вновь участвуют в следующем расчёте.

Для Supabase скопируйте `.env.example` в `.env`, задайте `DATA_SOURCE=supabase`, `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`, затем примените `supabase/migrations/001_initial_schema.sql` и `supabase/seed.sql`.

Активный расчёт и точный оптимизатор написаны на TypeScript, чтобы демо запускалось одной командой через npm. Папка `analytics/` содержит отдельный Python-прототип и не вызывается backend'ом. Её зависимости устанавливаются командой `python3 -m pip install -r analytics/requirements.txt`.

В демо данные хранятся в памяти процесса: после перезапуска backend ручные назначения и добавленные менеджеры сбрасываются. Для постоянного хранения подключите Supabase.

Подробности: [локальная разработка](docs/LOCAL_DEVELOPMENT.md) и [REST API](docs/API.md).
